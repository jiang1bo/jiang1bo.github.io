# 系统备份


备份的目标不只是“保存一份文件”，还包括在文件误删、硬盘损坏、系统故障或批量装机时，能够按需要恢复数据或重建系统。

# 热备、冷备与系统部署备份方案

选择方案前，先区分**数据备份、系统镜像、同步和系统部署**：它们解决的问题不同，不能互相替代。

## 一、热备与冷备

- **热备（在线备份）**：设备或系统继续运行时执行备份。适合日常、定时或持续保护数据；备份过程对业务影响较小，但需确认工具是否支持一致性快照。数据库、虚拟机等正在写入的数据，最好使用支持应用一致性或快照的方案。
- **冷备（离线备份）**：关机或停止相关服务后再备份。适合制作系统盘、磁盘分区的完整镜像，数据状态通常更容易保持一致，但需要安排停机时间。
- **快照不等于备份**：快照通常依赖原设备或存储系统；设备损坏、勒索软件或误操作可能同时影响快照。重要数据还应另存到独立介质或异地位置。
- **同步不等于备份**：同步通常会把删除和错误修改也传播到目标端。需要保留历史版本或使用带版本控制的备份任务。

建议采用 **3-2-1** 原则：至少保留 3 份数据副本，使用 2 种不同介质，其中 1 份放在异地；条件允许时，再增加离线或不可变副本，并定期验证恢复。

## 二、Windows 系统与数据备份

| 方案或工具                            | 适用场景                                     | 使用要点                                                     |
| ------------------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| Windows 原生功能                      | 文件历史记录、系统保护、系统映像或服务器备份 | 还原点主要用于回退部分系统状态，不能替代完整系统镜像和独立数据备份。 |
| DISM++                                | 通过 WIM 等映像格式备份或恢复 Windows 系统   | 可用于制作和维护系统映像；在线备份能力与系统状态、卷影复制及工具版本有关。重要系统建议在恢复环境中操作，并实际验证映像可恢复。 |
| Ghost                                 | 磁盘或分区镜像、特定环境下的系统克隆         | 需确认版本与硬件、启动方式及磁盘格式兼容；旧版本可能不适用于较新的 UEFI、GPT 或存储控制器环境。 |
| 傲梅等备份工具                        | 系统、文件、磁盘或分区备份，以及磁盘克隆     | 常见功能包括定时任务、增量或差异备份、邮件通知及系统迁移；具体能力、支持的系统和存储目标以对应版本的官方说明为准。 |
| 驱动天空 NS5                          | 驱动管理、系统封装或母盘制作等部署工作       | 更偏向系统部署和驱动处理，不应单独作为重要数据的长期备份方案。 |
| NAS Active Backup for Business（ABB） | 集中管理电脑、服务器或虚拟机备份             | 适用系统、机型、代理程序和恢复方式依 NAS 型号及 ABB 当前支持范围而异；部署前核对官方兼容列表并测试整机恢复。 |

### Windows 备份建议流程

1. 明确要保护的是个人文件、系统分区，还是整块磁盘。
2. 将映像保存到**非系统盘**，并再复制一份到移动硬盘、NAS 或异地存储。
3. 按业务重要性设置频率，例如文件每日备份、系统映像在重大更新前或按月制作。
4. 为备份保留历史版本，避免最新一份备份覆盖了可用的旧版本。
5. 定期检查备份日志，并抽样恢复文件；关键系统应验证完整恢复流程。

如果使用 WIM 映像，可采用清晰、可检索的命名方式，例如 `D:\Sys_Backup\Sys_Full_Backup-日期-Windows版本.wim`。排除列表应谨慎配置，避免把重要业务数据或用户配置误排除；高压缩通常会增加备份耗时，选择时应结合存储空间与备份窗口评估。

## 三、Linux 系统与数据备份

- **rsync 定时传输**：适合将文件定时复制到 NAS、另一台服务器或指定目录。建议使用 SSH、日志记录和明确的删除策略；需要保留历史版本时，应搭配快照、版本目录或专用备份工具。
- **磁盘镜像**：可使用 Clonezilla 等适合离线克隆与恢复的工具。直接使用块级镜像前，需确认目标磁盘容量、分区布局和启动方式；不要把普通文件同步误当作可启动的系统镜像。
- **NAS 备份**：若 NAS 和代理程序支持相应 Linux 发行版，可将 Linux 主机纳入集中备份。先核对兼容性、权限和恢复限制，再进行试恢复。

rsync 示例（将目录同步到远端；执行前应先检查路径和删除选项）：

```bash
rsync -a --delete /data/ backup@nas:/volume1/backup/server-data/
```

`--delete` 会删除目标端中源目录不存在的文件。若目标端需要保留误删文件或旧版本，不要直接依赖这类单向镜像命令，应使用带快照或版本保留的方案。

## 四、SyncBack 的定位与主要能力

SyncBack 可用于 Windows 上的文件备份和同步，也可与支持的远程服务或 SyncBack Touch 配合。典型工作方式是选择源和目标，设定任务计划、比较规则、版本保留和通知方式，再定期运行任务。

常见能力包括：

- **备份与同步**：配置新增、修改、删除等情况的处理规则。执行前应仔细检查双向同步和删除传播设置。
- **版本控制与 Delta-Copy**：在对应版本和目标类型支持时保留文件历史，或只传输文件变化部分，适用于大型文件及带宽受限场景。
- **远程存储**：支持范围可能包括 FTP、FTPS、SFTP、NAS、云存储和 WebDAV 等；不同版本、协议引擎和服务端的兼容性并不相同。
- **并行传输与压缩**：可提高部分场景下的传输效率，但实际速度受网络、目标服务和文件类型影响。
- **SyncBack Touch**：用于让 SyncBack 访问受支持设备上的文件；连接数量、操作系统和功能范围应以官方文档为准。
- **集中管理**：SyncBack Management Service 面向多台设备的管理、监控和报告。

建议优先从简单的单向备份任务开始，确认日志和恢复结果正常后，再启用复杂的双向同步、差异传输或删除规则。官方网站：[2BrightSparks](https://www.2brightsparks.com/)。

## 五、系统恢复、启动介质与批量装机

- **传统 ISO 安装**：适合单台设备或少量设备，启动安装介质后逐台安装。
- **Ventoy**：制作多 ISO 启动 U 盘，便于携带和启动不同系统镜像；它主要解决本地启动介质管理问题，不等同于网络批量部署。
- **iVentoy 与 PXE**：可通过网络启动为多台设备部署系统，适合有线网络环境下的批量装机。需准备兼容的启动镜像，并配置好 DHCP/PXE 网络环境。
- **网刻或其他 PXE 启动方案**：可用于批量安装或恢复，但应确认镜像、网卡驱动、启动模式和磁盘布局适配目标设备。

部署前应先在一台测试设备上验证镜像、驱动、启动方式和恢复流程。系统镜像用于快速恢复或部署，用户数据仍应通过独立的数据备份任务保护。

## 六、选型速查

- **保护个人文件**：Windows 文件备份工具或 SyncBack，目标可选 NAS、移动硬盘或受支持的云存储。
- **快速恢复 Windows 系统**：系统映像工具或 NAS 集中备份，并保留异地副本。
- **保护 Linux 目录**：rsync 配合版本保留、快照或集中备份系统。
- **制作系统母盘或批量装机**：驱动和封装工具、经验证的系统镜像、Ventoy 或 PXE/iVentoy 部署。
- **重要业务、数据库或虚拟机**：选择支持一致性快照和应用一致性的方案，并执行恢复演练。

**安全说明：**不应使用来历不明的 KeyGen、破解补丁或修改 hosts 文件绕过授权。安装和激活请使用官方安装包、试用版或合法授权；具体功能和静默安装参数应以对应版本的官方文档为准。
