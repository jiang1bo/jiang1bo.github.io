## 初遇

老运维讲起祖师爷那会儿，跟讲段子似的：一台机器一个系统，排障全靠走进机房，看屏幕、听风扇、摸机箱烫不烫，一张报纸、一根烟、一个bug修一天。监控只有 up 和 down，没有中间态。没工具，没文档，全凭肉身硬扛——眼睛当监控，手当负载均衡。停机叫“技术性调整”，Bug 叫“功能特色”。这不是段子，当年真是这么往外说的。

后来业务涨得比人头快，手工扛不住了。据说当年 Red Hat 推出 Kickstart，老师傅们顿觉身价倍增：再也不用刻光盘、一台一台装 Linux 了。只要搞定 PXE、DHCP、TFTP，再写一屏眼花缭乱、不知所云的 Kickstart 脚本，然后像哈利波特一样轻点魔棒，上百台服务器瞬间装完。这堆花里胡哨的东西可不好整——没有大专以上学历、过不了英语四级，根本别想玩转。结果没几年，Cobbler 出来了。中文名“补鞋匠”，名字听着苦，用起来跟楼下摊煎饼一样，闭着眼打两个蛋。装机门槛从大专掉到初中。

## 入行

而此时的我，还是个憧憬未来的小男孩，正被电视广告反复洗脑：“姐，遇到新东方的厨师就嫁了吧。”我认定运维工程师就是这么个职业：体面，稳定，饿不死。于是带着这点朴素的幻想，我入了行，光荣地成为一名装机民工（学名：linux运维工程师）——一份很有前途的职业。

然后，Ansible 来了。

Docker 来了。

Kubernetes 来了。

进入云计算时代了。

我只能跟着卷：修磁盘满、查 TIME_WAIT、写 Shell 巡检，主打人肉翻面；再补 DevOps、SRE 那一套——tcpdump 抓包定位断网，砍 Docker 镜像体积，在 Grafana 上盯 Prometheus，盯得像看心电图。GitOps、服务网格挨个卷了一遍，eBPF 啃了两口，没啃动。

后来我发现：我们把基础设施越搞越复杂，复杂到自己都看不懂了。以前老师傅们，手眼合一就是全部工具的时代早已不复返。集群里的 Pod 生生死死，告警一天响一万次。以前排障，SSH 连上去看一眼；现在排障，像在一万块玻璃后面找一只跑丢的蚂蚁。

## 现状

最后，2023 年，AI 来了。

以前自嘲“人肉运维”，现在 AI是直接来掀摊子的。老板们刷着大模型的新闻热血沸腾：输一条指令，AI 自动排查、自动扩容、自动修复，摊煎饼的这批人可以散了。半夜刷 agent demo，我也慌过。慌完想明白一件事：AI 会写脚本、会查日志，但它不能替你背锅。让它自动重启核心数据库，崩了谁签字？被 prompt 骗了真执行 rm -rf /*，追责追到谁头上？

所以我的结论：未来不缺会颠勺的运维，缺的是给 AI 立规矩的那个人。规矩里立住了，这AI才用着不烧心。
